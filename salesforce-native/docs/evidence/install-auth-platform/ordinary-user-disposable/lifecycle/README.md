# Ordinary human OAuth lifecycle: offline preparation

Nothing in this directory is live approval. The controller must obtain human approval of this exact scope before any org mutation or live CLI execution. Imports and tests are network free. No production ingress, auth files, or force-app changes are included.

## Private pins and explicit adapter

Controller privately freezes config with `org`, `actor` (normalized checksum18), `clientId`, `loginOrigin`, `instanceOrigin`, `identityOrigin`, `siteOrigin`, and `callback` exactly `http://localhost:1717/OauthRedirect`. Origins are HTTPS origin strings only, exact equality; no suffix or broad Salesforce allowlist. Config and vault must be outside the repo in an operator-owned private directory, mode 0600 files. Never record IDs, auth URL, code, state, bearer, username or credentials in public receipts. Pins come from independently approved org/app/user evidence, not token claims. The public ECA client ID is frozen privately; no password/client secret is accepted.

After approval only, `node controller.cjs --live --human-approved open PRIVATE_CONFIG PRIVATE_VAULT` binds 127.0.0.1:1717 and explicitly opens `/usr/bin/open` with the private authorization URL. There is no default auth opening or URL printing. The callback Host is exactly localhost:1717; state, singular code/state, callback, S256 and five-minute acquisition expiry are enforced. The user types their own password and authorizes; never LoginAs/runAs OAuth. Each transport has a 15-second timeout, redirects forbidden, no retries. Returned access and refresh credentials are saved privately before grant validation. The vault uses opaque owned credentials internally; status output has no bearer handles. Core injected transport/vault supports a controller-managed equivalent; persist privately before returning from write.

After evidence controls, `node controller.cjs --live --human-approved revoke PRIVATE_CONFIG PRIVATE_VAULT` revokes exact owned access then refresh separately. A failure retains credentials and per-token success markers; controller investigates before deliberately running another command (no automatic retry). Successful revocation retains access for revoked-token measurements. Only after standard REST 401 and probe 401: `node controller.cjs --live --human-approved purge-after-measurement PRIVATE_CONFIG PRIVATE_VAULT`. This explicit purge is a controller attestation that measurements are complete, not independent measurement proof. Remove any controller private duplicates separately and receipt only success/failure. Never delete a credential while revocation is uncertain.

The CLI is single-controller tooling: do not run simultaneous operations; operator serializes the entire lifecycle. It does not create Salesforce users, ECA, Site metadata or permissions. Oversized/invalid token responses fail closed; credentials that cannot be parsed cannot be retained, so stop and investigate owned app sessions before cleanup. No refresh exchange is needed.

## Measurements and teardown

Use the same real ordinary token throughout: `noUse`, `use`, `admin`, `unknown`, `nested`, `guest`, `fabricated`, `revokeUse`, `validToken`, `revokedToken`. Before each named control validate exact identity and standard REST global sobjects 200; no CRM rows. Freeze profile/effective permissions evidence; do not manufacture an admin token for an ordinary control. After removing the owned Cardstack_User assignment, next call must be 403 with the same valid token. At revokedToken stage carry pre-revoke controls; do not demand a post-revocation identity 200. Revoke exact access/refresh, measure retained bearer standard REST 401 and probe 401, then purge. Every unexpected status stops promotion to a success claim.

Cleanup remains controller owned and must run even after failed acquisition or measurement. Restore Site inactive **before** removing exactly owned guest grant IDs. Verify current IDs, metadata digests and dependencies against creation ledger before removal; abort deletion on drift or unowned dependents. Remove owned Cardstack_User and temporary probe assignments by recorded assignment IDs; never delete an existing assignment. Delete only exact owned probe metadata and temporary permission set from frozen cleanup manifest after dependency guards. Delete only new ECA name plus post-creation ownership/digest validation, preserve other four ECAs. Deactivate owned user after session revocation (never delete). Verify Site inactive, grants/assignments absent, owned metadata/ECA absent, user inactive, deploy JWT ON and unrelated ECAs unchanged. Public cleanup receipts use booleans/counts/digests, no raw IDs or credentials. Failed cleanup is unresolved, never silently marked complete.

Full production conformance, MCP resource/recipient mapping, fresh ChatGPT callback and portability remain unresolved. Offline tests are controller safety evidence, not a live user or client proof.

Initial persistence failure remains an unresolved-session condition.
