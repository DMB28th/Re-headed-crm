## Immutable history and current contract

Stage A remains **75 Pass / 2 Fail / 7 Unknown**. Its two original unreserved-letter negative cases failed v1's expected404; their actual response status/body was not captured. Stage C does not reconstruct those missing responses or rewrite those failures. The seven original Unknowns remain four fabricated-bearer provider outcomes, two HTTP metadata redirects and one resource request stopped before HTTP by the context guard. A later supplemental public resource case passed separately.

The user-approved prospective v2 criterion accepts equivalent unreserved-letter spelling, with GET405/`method_not_allowed` for canonical and encoded-letter paths. Stage C's four plain/lowercase observations support that portion only. Uppercase-letter equivalence and lowercase/uppercase reserved-separator rejection are future live product criteria. Reserved-separator GET404/`unknown_probe_route` is an explicit product route requirement, not an inferred platform guarantee. No raw URI visibility, normalization layer, generic percent decoder or decoder workaround follows from these observations.

The accepted authorization architecture delegates opaque-bearer authentication and bounded org/API rejection to Salesforce, then enforces fresh explicit Cardstack permissions and enabled setup intent. The exact token-app accessor and per-client path audience prerequisites were superseded; do not reopen them. Exact RFC8707 mapping stays Unknown. Canonical resource/issuer metadata remains required, but publishing those strings does not prove token mapping or full MCP authorization conformance.

## Task 3 evidence acceptance

Task 3 consumes Task 2 Access/Context/Setup. Its reviewed source boundary must establish all of these before it is accepted as implemented:

- Guest can obtain only canonical public discovery/metadata and the MCP401 challenge with its exact metadata pointer. Guest POST tools/call and resources/read must fail before private dispatch; no private setup or diagnostic state in responses.
- Named execution checks explicit Use freshly on every call and requires enabled setup intent. Missing or just-removed Use returns403; Manage-only authority is not a substitute. Salesforce authentication remains outside unit-test simulation; no bearer parsing, token introspection or outbound callouts.
- Validate only supported canonical Site-prefix/context and exact client/endpoint routes; refuse unknown, nested, extra, case-altered and query-bearing routes as specified. Test approved v2 letter equivalence separately from reserved-separator rejection, with the exact v2 GET status/error criteria. Do not decode arbitrary paths or infer platform URI representation from injected tests. Live reserved-separator rejection must be measured before product exposure/release acceptance.
- Return raw-empty202 for valid notifications; support initialize versions `2025-06-18` and `2025-11-25`. Enforce the16KiB body cap, reject batches, and test deterministic malformed JSON, bad params, unknown methods/resources and method/route errors without leaking request data.
- Keep Dispatcher private; guest class grant is Ingress only. Advertise only the diagnostic tool/resource contract, including app-only echo visibility; no CRM/HXL aliases. Resource lookup uses `WITH USER_MODE` and a constant resource name. Verify zero CRM DML and no callouts.
- Until Task 4 supplies the diagnostic service and Task 5 supplies the real resource, return explicit diagnostic/resource unavailable results. Injected resource tests establish source behavior only; they do not prove HTML loading or actual host success.

These criteria follow the [Task 3 plan](../../superpowers/plans/2026-10-08-mcp-apps-install-auth.md#task-3-production-rest-boundary-and-synthetic-mcp-dispatcher); the [approved spec](../../superpowers/specs/2026-10-08-mcp-apps-install-auth-design.md) remains binding. Any stale exact-app/path prerequisite wording must be read under the accepted model above.
