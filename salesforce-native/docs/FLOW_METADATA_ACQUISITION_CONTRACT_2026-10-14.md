A Flow's system-mode declaration cannot expand Cardstack authority; explicitly reject system-mode semantics rather than promising equivalent execution.

## Stable proposed contract

`CardstackFlowPlan` uses `schemaVersion: cardstack-flow-plan/1` and `compilerVersion: cardstack-flow-compiler/1`. Its Salesforce-only `identity` contains `definitionId18`, `versionId18`, `versionNumber`, `namespace`, `apiName`, acquisition `apiVersion`, source Flow execution API version and `sourceHash`. `entryNode`, ordered `nodes`, typed scalar `resources`, `readSet`, `writeSet` and the exact navigation/visibility semantics comprise the normalized executable body. Each resource declares `name`, scalar `type`, `isCollection: false`, and `origin: INPUT | CONTEXT | COMPUTED`; current record identity is immutable CONTEXT. Screen fields are distinct writable resources, never arbitrary input-map keys. Operands are tagged `literal`, `resource` or `currentRecordField`, with explicit scalar type and no arbitrary expression string.

Publication is a separate immutable envelope `{revision, planHash, policyRevision, compatibilityReportHash}`. `planHash` covers the canonical executable body including identity/compiler/schema versions and excludes the whole publication envelope. The source hash covers the complete acquired metadata, including fields intentionally classified as presentation-only. Publication always produces a new revision; rollback repoints to a previously validated publication rather than mutating its plan. Apex rechecks stored hashes/versions when loading. No browser-supplied graph, cursor, resource defaults, hash or compatibility verdict has authority.

`CardstackFlowCompatibilityReport` is bound to identity/source hash/compiler version, policy revision and relevant schema capability fingerprint. Verdicts are `SUPPORTED`, `UNSUPPORTED`, or `ACQUISITION_FAILED`; never `partial` or speculative `full`. Issues contain stable `code`, metadata `path`, safe `elementName`, `reason`, and `blocksStart: true`. Acquisition errors distinguish missing/unavailable metadata, denied access, stale selection, unsupported source API and identity mismatch; none is silently an empty list. Non-blocking presentation differences are explicit notices, not omitted semantics.

Proposed bounded interpreter supports acyclic Screen/SET Assignment/typed Decision and one terminal CURRENT_RECORD update through the existing native confirmation writer. Sections are typed nested groups; scalar types must match existing writer/control capabilities. String, whole-number, Boolean, static single-select and explicitly supported decimal-as-string controls are separate capabilities; scale-2 Number must not be silently treated as Integer. No general formula evaluator. Typed predicates permit exact AND/OR lists only, not numbered condition logic. Updates require an immutable current-record target, exact supported assignments, no extra filters, no collections, no connector after save and no fault connector. Fail before start for actions, subflows, lookups beyond explicitly defined current-record reads, loops, dynamic choices, collections, uploads/custom components, pause/waits, create/delete, unsupported validation/retention/run-mode semantics or unknown executable properties.

Use the interpreter workstream's proposed limits: 32 nodes, 8 screens, 20 inputs per screen, 40 scalar resources, four group levels, 32 automatic nodes per request, 64 KiB normalized plan, 32 KiB private state and 16 KiB request arguments. These are proposed product limits, not measured governor guarantees. Compatibility validates unique names, exact start, all connectors/references, acyclicity, reachable terminal paths, typed defaults/operands, answer ownership, permitted write target/fields and absence of unimplemented non-null semantics. Explicitly whitelist harmless layout properties; null/empty schema padding is distinct from unknown populated properties. Reject cycles including unreachable nodes, and report unsupported constructs anywhere in the source to avoid misleading admin support labels.

The acquired probe is presently **uncompiled/unpublished**. Its decimal input, display interpolation and `styleProperties` width/alignment require declared compiler adapters; it cannot receive a machine `SUPPORTED` verdict merely because legacy code understands screen arrays. Its lack of update/sections also keeps the milestone acceptance gate open. The full raw fixture must stay private; tests can use an independently authored sanitized structural derivative clearly labeled synthetic, plus private real-fixture execution evidence.

## Drift, cancellation and handoff policy

Active source drift does not mutate an existing published plan or in-flight state. An admin refresh discovers drift and requires a new compatibility review/publication. New starts use the exact current published revision and do not re-resolve Salesforce's active version. An in-flight run is pinned to its immutable plan; any publication/policy revision change invalidates it before further transitions or writes, consistent with existing governed-editor invalidation. No transparent migration of answers or pending confirmation. If active source changes without a new Cardstack publication, the existing explicitly published plan remains pinned; Studio must show that it differs from the current active Salesforce version. This policy avoids giving ordinary users metadata privileges or pretending runtime performs an active-version refresh.

Cancel locks and terminates the private interaction, revokes pending confirmation and preserves an existing saved receipt. Back is permitted only when the compiled screen allows it; it restores the interpreter's defined screen checkpoint and invalidates review. A completed terminal write cannot navigate Back or claim cancellation undid it. Unsupported metadata is rejected before any interpreted run. Optional **Open in Salesforce** clearly starts a fresh native interview with current trusted context; it does not resume the interpreted cursor, transfer saved side effects or guarantee the same active version. Cancel the old interpreted run before handoff; no automatic fallback after a write.

## Required verification before delivery

Positive acquisition: exact active selection, one-row metadata retrieval, definition/version match, checksum18, active-pointer stable read and explicit permission-denied/null-metadata behavior. Compiler: supported two-screen grouped fixture, typed answers/defaults, output escaping, explicit unsupported-element/path reasons, duplicates/dangling references/cycles, unknown populated properties, alternate filter logic and write-target injection. Versioning: source drift during acquisition/publication, compiler mismatch, plan tampering, publication change during review, rollback and cancellation/replay. End-to-end: a real existing Flow with sections and one supported current-record terminal update, native compilation/publication, ordinary-user traversal/Back/Cancel, exact review/confirm, repeat-safe receipt and independent Salesforce read-back in ChatGPT and Claude. CLI acquisition and local synthetic tests satisfy only their stated boundaries.
