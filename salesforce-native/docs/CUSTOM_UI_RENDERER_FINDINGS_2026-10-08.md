# Custom renderer source audit — 2026-10-08

The React renderer is a useful presentation foundation, but it cannot safely be connected to the current native tools by renaming calls. Reuse controls and visual composition; rebuild the transport DTOs and revisioned state adapter around Apex and published Studio configuration. Retiring HXL is the requested presentation direction, not evidence that its custom replacement already works under Salesforce-only hosting.

Scope: read-only audit of authoritative source in `/Users/danielben-atar/Re-headed-crm`; no changes to `apps/`, `packages/`, or native source, no dependency installation, deploy, or live calls. File links below are verified against current source. Runtime exploitability, platform support, and host behavior have not been freshly tested. Apex authoring/analyzer/test execution phases are N/A because no classes were generated or updated; this report makes source conclusions only.

## Reuse / rebuild / drop

| Surface | Decision | Migration requirement |
|---|---|---|
| Record layout, header, sections, drill-through, provenance, diff/receipt views | Reuse presentation | Hydrate with a versioned, filtered native DTO; fresh read after save; honest errors. |
| Text/integer inputs and dirty markers | Reuse with corrections | Explicit empty/null/clear behavior; server-supported controls only. |
| Picklist, lookup, boolean, date, datetime controls | Keep as later candidates | Describe metadata and typed contracts must be implemented and proven. Their presence in TSX does not extend the Account editor's supported field types. |
| `WidgetHost` abstraction and self-contained HTML bundling | Reuse pattern | Salesforce-hosted MCP resource/transport, per-user identity, host negotiation and versioned resource URI still need proof. |
| `useWidget`, shell, local async state machines | Rebuild bridge/state adapter | Runtime payload validation; identity/revision guards; cancellation; loading, unknown outcome and retry states. |
| Legacy `crm_*` call shapes, optional confirmation, Node config/auth/audit | Drop as production authority | Map to governed Apex services; do not restore retired backend/tenancy/accounts/Postgres. |
| Flow field renderer, sections and bounded interpreter concepts | Carry forward selectively | Rebuild durable actor-bound sessions and bounded capability checks in native services; identify it as an interpreter, not full Salesforce Screen Flow execution. |
| Embedded-flow iframe and “Live in chat”/“nothing was run” blanket labels | Drop from first slice | Unsupported runtime/CSP/session assertions; presentation must reflect actual execution evidence. |
| Flow delete confirmation | Drop | Conflicts with the no-delete-record invariant. |
| Home task check-off and results pagination | Rebuild before enabling | Current async confirmation and query continuation defects below. |
| Shared runtime/Studio preview concept | Preserve design goal | Existing React preview sharing is for retired Next Studio; it does not establish parity with native LWC Studio. |

## Actionable findings

1. **P1 — Edit/confirmation state survives replacement with another record or policy.** The payload effect resets navigation, search and lookup labels, but never `mode` or `lastDraft` ([card.tsx:84](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:84)). The shell mounts the same component without an identity key ([mcp-app.tsx:58](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/mcp-app.tsx:58)). Reviewing/writing handlers use the current layout/object/id with the retained draft or preview ([card.tsx:189](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:189), [card.tsx:224](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:224)). A draft can therefore be presented for another record; a prior confirmation can appear beneath the new header. Apex binding should reject mismatched tokens, but cannot repair this UI. Bind UI state and responses to actor/object/record/policy/interaction/revision; invalidate old async completions; preserve drafts only for the same authorized interaction.

2. **P1 — A write transport failure is incorrectly presented as proof that nothing was written.** The catch restores confirmation, while the view always appends “Nothing was written” ([card.tsx:261](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:261), [card.tsx:420](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:420)). A lost response after commit has an unknown outcome. Add an unknown-outcome state that queries the interaction/receipt or repeat-safe operation; do not mint a replacement grant automatically. Apex already stores/replays successful receipts ([CardstackUpdateRecordAction.cls:40](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackUpdateRecordAction.cls:40), [CardstackConfirmToken.cls:29](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackConfirmToken.cls:29)).

3. **P1 — Home task confirmation races the preview and can reuse a prior token.** `beginConfirm` changes state before awaiting preview; Confirm is immediately enabled. Existing tokens are not cleared; completion includes the token only if present. Neither async call catches transport rejection ([home-card/card.tsx:150](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/home-card/card.tsx:150), [card.tsx:165](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/home-card/card.tsx:165), [card.tsx:199](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/home-card/card.tsx:199)). A rep can confirm before the server prepares the review; preview rejection after cancellation can repopulate token state. Add a distinct preparing state, clear prior grants, disable Confirm until a validated current preview exists, guard late results, and handle unknown write outcome. Reset task state on actor/payload/session changes.

4. **P1 — No validated adapter exists between legacy payloads and native DTOs.** The hook merely casts `structuredContent` ([use-widget.ts:47](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/shared/use-widget.ts:47)); preview and write paths accept unchecked casts ([card.tsx:207](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:207), [card.tsx:240](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:240)). Legacy expects `{object,id,patch}` and `changes[{field,before,after}]`, plus a receipt containing fresh `record.fields`. Apex expects `{recordId,changes:[{fieldApiName,newValue}]}` and returns display-string `beforeValue/afterValue`, `outcomes`, `dmlFailed`, and no legacy fresh-record object ([CardstackPreviewUpdateAction.cls:69](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackPreviewUpdateAction.cls:69), [cls:187](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackPreviewUpdateAction.cls:187), [CardstackUpdateRecordAction.cls:284](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackUpdateRecordAction.cls:284)). HXL edit responses are another shape and require interaction key, expected revision and clicked review reference ([CardstackRecordEditAction.cls:20](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditAction.cls:20)). Define a versioned custom-UI DTO; reject malformed/wrong-kind/wrong-identity results before transitioning. Do not synthesize a successful receipt from field outcomes when `dmlFailed=true`: the failed single-record DML can leave unrelated outcomes marked success ([CardstackUpdateRecordAction.cls:123](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackUpdateRecordAction.cls:123), [cls:187](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackUpdateRecordAction.cls:187)).

5. **P1 — Legacy write semantics must not be carried over.** The legacy tool permits absent confirmation and describes that as model-initiated ([server.ts:1327](/Users/danielben-atar/Re-headed-crm/apps/mcp-server/src/server.ts:1327)). Native confirmation is mandatory and binds the complete submitted patch, actor, policy and record freshness ([CardstackPreviewUpdateAction.cls:111](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackPreviewUpdateAction.cls:111), [CardstackConfirmToken.cls:14](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackConfirmToken.cls:14)). Drop the unconfirmed-model-write lane entirely. Editing local values and previewing them never authorizes execution.

6. **P1 — Flow renderer cannot use current native Flow Continue as its interview engine.** It sends `interviewState`, `back`, `confirmWrite` and a typed answers map ([screen-form.tsx:411](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:411)). Native accepts a patch-entry list and only refreshes a Salesforce launch card; it explicitly does not execute or submit flow inputs ([CardstackFlowContinueAction.cls:13](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackFlowContinueAction.cls:13), [cls:52](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackFlowContinueAction.cls:52), [cls:89](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackFlowContinueAction.cls:89)). Cancellation sends `confirmWrite:false` through continue, and normal screens have no Cancel affordance ([screen-form.tsx:492](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:492), [tsx:524](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:524)). Build a separate bounded native interpreter contract with durable cancellation; do not reinterpret these launch endpoints as a full engine. Delete UI is explicit at [screen-form.tsx:448](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:448).

7. **P1 — “Server-sanitized” flow HTML has an insufficient source boundary.** Display text goes directly into `dangerouslySetInnerHTML` ([screen-form.tsx:136](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:136)). The legacy sanitizer strips certain tags and event attributes, but does not enforce an element/attribute/URL allowlist; a `javascript:` link is untouched ([flow-interview.ts:466](/Users/danielben-atar/Re-headed-crm/packages/core/src/flow-interview.ts:466)). This establishes sanitizer insufficiency, not a demonstrated exploit in a real host; host CSP may block particular execution. Use plain text initially or a proven allowlist sanitizer; reject unsafe URL schemes; do not rely on iframe sandboxing to validate content. Current resource registration also declares no frame domains for the embedded iframe ([server.ts:403](/Users/danielben-atar/Re-headed-crm/apps/mcp-server/src/server.ts:403), [flow-run/card.tsx:139](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/card.tsx:139)).

8. **P2 — Ad-hoc pagination loses query identity.** Show More calls search with only object and cursor, dropping search/filter/sort/limit ([table.tsx:67](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/results-table/table.tsx:67)). Legacy server rebuilds each query from supplied arguments ([server.ts:493](/Users/danielben-atar/Re-headed-crm/apps/mcp-server/src/server.ts:493)); the Salesforce cursor is only an integer offset ([salesforce-adapter.ts:944](/Users/danielben-atar/Re-headed-crm/packages/crm-adapters/src/salesforce/salesforce-adapter.ts:944)). Subsequent rows/counts can describe a different query. Bind continuation to the original query/policy/actor or return an opaque server-owned query cursor. Guard in-flight pages against new payloads; surface pagination errors (current code has only `finally`).

9. **P2 — Flow values/visibility/reset require correction before interpreter reuse.** Form reset depends only on screen name and step index, not session/revision ([screen-form.tsx:381](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:381)). Required checking walks children without inheriting a hidden section's visibility; answers sends all retained values, including hidden fields ([tsx:22](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:22), [tsx:388](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:388), [tsx:539](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:539)). Unsupported visibility operators default to showing fields ([tsx:78](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:78)). DateTime inputs echo timezone-less local strings ([tsx:95](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:95), [tsx:169](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/screen-form.tsx:169)). Define server/client shared bounded visibility semantics, ancestor visibility, hidden-value policy, and explicit timezone conversion; fail closed on unsupported definitions.

10. **P2 — Action identifiers and host failures are lost in conversational dispatch.** Flow/quick-action handlers send only label and record id, discarding API action identity ([card.tsx:304](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/card.tsx:304)); native requires the published action name, including mapping semantics ([CardstackRecordEditAction.cls:22](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditAction.cls:22), [CardstackRecordEditService.cls:25](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditService.cls:25)). `sendMessage`, `openLink`, and model-context errors are silently swallowed ([mcp-app.tsx:19](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/mcp-app.tsx:19)); flow launch marks opened regardless of host outcome ([flow-run/card.tsx:86](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/flow-run/card.tsx:86)). Use exact governed action identifiers and awaited bridge methods with capability-aware failure UI.

Additional control limits: legacy coercion maps empty text to null and numbers through JS `Number` ([edit-machine.ts:29](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/edit-machine.ts:29)). Native exact-answer transport distinguishes explicit `clear` from `answer`, and its editor currently supports only Account STRING/TEXTAREA/INTEGER ([CardstackRecordEditService.cls:18](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditService.cls:18), [cls:75](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditService.cls:75), [cls:133](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditService.cls:133)). Keep exact raw input and explicit typed/null intent until Apex canonicalization; do not silently broaden decimal/date/lookup support. Lookup's response guard also does not advance its sequence when closing or shortening a query ([editors.tsx:321](/Users/danielben-atar/Re-headed-crm/packages/widgets/src/record-card/editors.tsx:321)); invalidate every effect cleanup.

## Native invariants to preserve

- Salesforce-hosted runtime; connected-user reads/writes with sharing and CRUD/FLS. Published Studio policy narrows access; drafts grant none ([CardstackPolicyService.cls:15](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackPolicyService.cls:15)).
- Actor, record, exact submitted values, policy revision, clicked review reference/revision, expiry and record freshness bind confirmed execution. Server locks the private interaction and rejects stale revisions ([CardstackRecordEditService.cls:45](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditService.cls:45)); Back/Cancel invalidate the previous grant ([cls:72](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordEditService.cls:72)).
- Durable state, repeat-safe completion, definitive receipt/read-back, and honest unknown outcomes. Never derive authorization from local UI mode, chat text, model context updates or a tool visibility hint.
- Never place Salesforce credentials/session values or interaction grants in static bundles, logs or model summaries. Treat tool payloads as host-visible; the old “hidden from model” comment is not a confidentiality guarantee ([payload.ts:1](/Users/danielben-atar/Re-headed-crm/packages/core/src/payload.ts:1)).
- No delete tool; no undocumented Aura/Flow runtime endpoint; bounded interpreter must declare supported elements and fail/fallback for unsupported definitions.

## Smallest acceptance slice

Use one published Account edit action mapping an existing text field and integer field (e.g. Description and NumberOfEmployees), through a custom MCP App and existing governed Apex interaction services. This tests richer editing without introducing Opportunity/picklist/decimal/date behavior. No flow engine, iframe, home write or pagination required for this slice.

1. Demonstrate Salesforce-only per-user OAuth/discovery, tool discovery, resource read and iframe initialize in each advertised host. Static HTML contains no record data or secrets; meaningful text fallback remains. A transport/resource API receipt alone is insufficient.
2. Show the published action and values; capture exact text/Unicode/quotes/whitespace, integer zero, explicit clear and unchanged values. Validate the custom DTO and correlate each response with the current interaction/revision. Preserve the existing one-field interaction service initially if needed; a simultaneous multi-field submission requires an explicit new service contract.
3. Review server-produced before/after; Back changes an answer and invalidates old review; Cancel durably refuses later execution. Confirm exact clicked review; independently read Salesforce and audit evidence; refresh the card. Repeated confirm and simulated lost response recover one persisted result.
4. Reject swapped actor/record/action, tampered value/grant/revision/reference, expired interaction, changed field access or published policy, and concurrent record modification. Predicted/final validation failure preserves answers and shows zero saved when the record DML failed.
5. Only claim replacement delivery after this slice passes on fresh package installation and each advertised client. HXL retirement can then remove the old presentation route while retaining its Apex governance; no external transport fallback is implied.
