# Cardstack Salesforce admin UX audit — October 13, 2026

Cardstack Studio should help Salesforce admins configure, govern, publish, and verify chat experiences. End users connect to their chat client with their Salesforce account and use those experiences separately. The main UX priority is trustworthy configuration: explain what is effective, make consequential changes reviewable, and preserve unfinished work.

## Priority 1: make publishing accurate and capabilities honest

**Observed source: the Publish Center can hide material changes.** Layout keys take a dedicated comparison path rather than the generic JSON comparison. Its `fieldList` recognizes flat `fields` or nested `recordCard.sections`, but the current builder removes those legacy fields and writes top-level `highlights` and `sections`. The comparison then considers only field identities and positions, omitting editability, actions, and write policy even for recognized shapes. Sources: [comparison dispatch](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackPublishCenter/cardstackPublishCenter.js:129), [field extraction](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackPublishCenter/cardstackPublishCenter.js:195), [builder serialization](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:462). The Publish Center source is unchanged between main and dynamic.

**Reproduced locally:** live configuration had `highlights: Name`, section field `Description` with `editable:false`, and `permissions.writeEnabled:false`. The draft added editable `NumberOfEmployees`, made `Description` editable, and enabled writes. Both extracted field lists were empty; the actual review output was **“No field changes — only ordering or metadata differs.”** Raw draft JSON remains available behind a disclosure, so the changes are not absent from storage; the human-readable review is misleading. [Raw JSON disclosure](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackPublishCenter/cardstackPublishCenter.html:83).

**Proposal:** compare the current schema, including highlights, sections, field position/properties, action definitions/mappings/enabled state, write enablement, and denylist. Show before/after values for consequential policy changes. Use **Save draft** and **Review & publish** consistently, with pending counts and durable navigation to the specific saved draft. Preserve the existing honest partial-batch outcome. Rename **Roll Back** to **Discard draft**: its service marks a draft Rolled Back and leaves published configuration untouched; it does not restore an earlier live version. [Discard semantics](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackConfigService.cls:166), [batch outcomes](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackPublishCenter/cardstackPublishCenter.js:286).

**Observed source: Audience/Assignment exceeds delivered routing.** `extraAudiences` is component state; Add Audience only appends a name and refreshes rows. Selecting an object clears it. Options are rebuilt from that array, without rehydrating saved audience names. However, saving a layout uses `layout:{object}:{audience}`, so nondefault layout records can persist; saying “all audience configuration is local” would be incorrect. [State reset/options](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:129), [Add Audience](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:1291), [draft persistence](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:1038).

The record action loads `layout:{object}:default`. The newer dynamic Opportunity renderer does not add audience routing: its card calls `CardstackPolicyService.resolve('Opportunity')`, and that resolver plus action definitions still load `:default`. No actor-to-audience resolver was found in the authoritative Apex or renderer path. [Record loader](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackGetRecordAction.cls:162), [new card](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackOpportunityMcpAdapter.cls:176), [policy resolver](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackPolicyService.cls:15), [action loader](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackRecordActionService.cls:48).

**Proposal:** disable or clearly label nondefault audiences as unsupported until durable membership, precedence, resolution, and effective access preview exist. Current **View as** selects a config key with sample values; it does not impersonate a user or demonstrate their Salesforce FLS. [Preview loading](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:953).

**Observed source: Home Card editing has no matching runtime consumer.** The JSON editor stages `homecard` and previews supplied values, while `CardstackHomeAction` assembles tasks, recent records, and pipeline totals directly, without reading it. Those sources are unchanged in dynamic. [Editor](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackHomeCardConfig/cardstackHomeCardConfig.js:7), [runtime](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackHomeAction.cls:28). **Proposal:** clarify or disable this publishing promise until the runtime consumes the configuration.

## Priority 2: organize Studio around the admin’s next decision

**Live observation:** Dashboard opened with expanded MCP Apps setup, both clients marked Needs verification, a long technical runbook ahead of dashboard content, legacy setup at 2/5, and org Connected. Contact configuration showed Audience Default (everyone), five nested tabs, and unconfigured sections. These are observed presentation states, not proof that the live org matches any checkout.

**Source corroboration:** delivery and dynamic insert connection setup ahead of legacy history; `expanded = true`. The guide contains Site ID, External Client Apps, seven-value diagnostics, observation receipts, history, and recovery. The dashboard separately hardcodes a Connected badge when org data renders. [Setup placement](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackSetupChecklist/cardstackSetupChecklist.html:2), [default expansion](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackConnectionSetup/cardstackConnectionSetup.js:14), [guide](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackConnectionSetup/cardstackConnectionSetup.html:14), [org badge](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackDashboard/cardstackDashboard.html:16).

**Proposal:** provide a concise overview of configured objects, drafts, activity, and actionable attention; move the full runbook to dedicated Setup. Distinguish Salesforce org context, per-client connection evidence, and CRM editing readiness. Retain truthful Unknown/Needs verification states: setup checkboxes record history or intent, not successful connections. Guide object setup through fields → allowed edits → actions → review → publish → real-client test. Keep advanced settings reachable without making admins decode architecture before configuring a card. Replace Lists JSON and API-name denylist entry with declarative pickers. [Lists editor](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.html:270), [denylist](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.html:407).

The newer dynamic ObjectConfig already adds an Opportunity Stage/Close date/Amount preset with prerequisite errors. This is a useful pattern to extend to other guided configuration, and means main's authoring scope should not be treated as the complete current feature set. Other principal Studio bundles match main byte-for-byte according to the coordinating agent's comparison. ## Priority 3: preserve work, roles, and accessible navigation

**Source findings:** object/audience switching loads replacement working models without a dirty-work guard. Dashboard data is wired/cached; the Studio shell coordinates navigation without refresh after saves/publishes. This is a stale-display risk, not a reproduced stale-count failure. Audit expansion uses a clickable `div` without keyboard semantics. Publish-all/rollback dialogs use custom modal markup, with no focus or Escape handling in their controller. [Switch handlers](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:507), [model reload](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackObjectConfig/cardstackObjectConfig.js:265), [dashboard wire](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackDashboard/cardstackDashboard.js:21), [shell](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackStudio/cardstackStudio.js:12), [audit control](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackAuditViewer/cardstackAuditViewer.html:79), [modal](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/lwc/cardstackPublishCenter/cardstackPublishCenter.html:140).

**Admin boundary qualification:** authoritative permission sets grant Studio controller/app access and configuration writes to Admin; User has published-config read access and no Studio controller grant. The checklist nevertheless says **“Cardstack_Admin or Cardstack_User to use the Studio and tools.”** General Studio controller/service paths rely on class access, sharing, CRUD/FLS, and object checks rather than an explicit admin-role gate. New connection setup independently calls `requireAdmin()` backed by `Cardstack_Manage_Connections`. This is a role-message inconsistency and enforcement-design distinction, not evidence of an exploit. A legacy split User permission file even exposes the app/tab while intentionally withholding the controller; it is not authoritative package metadata. [Admin grants](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/permissionsets/Cardstack_Admin.permissionset-meta.xml:3), [User grants](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/permissionsets/Cardstack_User.permissionset-meta.xml:3), [checklist](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackStudioController.cls:318), [service checks](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackConfigService.cls:122), [explicit new gate](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/force-app/main/default/classes/CardstackConnectionAccess.cls:6), [legacy metadata](/Users/danielben-atar/.codex/worktrees/dynamic-lookup/Re-headed-crm/salesforce-native/permissions/force-app/main/default/permissionsets/Cardstack_User.permissionset-meta.xml:66).

**Proposal:** preserve admin-only enforcement; explain Admin for configuration and User for chat. Add save/discard protection during context changes and invalidate affected wired summaries after mutations, following [Salesforce caching guidance](https://developer.salesforce.com/docs/platform/lwc/guide/apex-result-caching.html). Use native buttons and keyboard-capable pickers; use [LightningModal](https://developer.salesforce.com/docs/platform/lightning-component-reference/guide/lightning-modal.html) for platform focus behavior, then verify against [Salesforce accessibility patterns](https://architect.salesforce.com/docs/architect/well-architected/guide/fairness-accessibility-patterns.html). Simplify repeated titles and consider removing the generic Salesforce Home app tab after confirming its purpose. [App navigation](/Users/danielben-atar/Re-headed-crm/salesforce-native/force-app/main/default/applications/Cardstack_Studio.app-meta.xml:14).
